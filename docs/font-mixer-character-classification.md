# 字体混排字符识别规则

本文档说明“字体混排”功能如何区分中文、英文、罗马数字和符号，以及各类字符应使用中文字体还是英文字体。

对应实现：`src/features/font-mixer.ts`

## 1. 总体原则

字体混排以完整文本内容为依据，将相邻且分类相同的字符合并成区间，再分别应用中文字体或英文字体。

识别优先级如下：

1. 明确的 Unicode 罗马数字；
2. 符合产品规则的 ASCII 罗马数字；
3. 用户指定的符号字体归属；
4. CJK、日文假名、全角字符及中文标点；
5. 其余字符归英文侧。

规则采用保守策略：无法可靠判断为中文或罗马数字的内容，默认使用英文字体，避免把正常英文、型号或产品编码错误地应用成中文字体。

## 2. 中文侧字符

以下字符默认使用中文字体：

- CJK 汉字；
- CJK 扩展区汉字；
- CJK 兼容汉字；
- 日文平假名和片假名；
- CJK 符号和标点；
- 全角及半角形式区中的全角字符；
- 符合本文规则的罗马数字；
- 用户点击“符号用中文”后，被识别为标点或符号的字符。

当前主要 Unicode 范围：

| 范围 | 含义 |
| --- | --- |
| `U+3000–U+303F` | CJK 符号和标点 |
| `U+3400–U+4DBF` | CJK 扩展 A |
| `U+4E00–U+9FFF` | CJK 统一表意文字 |
| `U+F900–U+FAFF` | CJK 兼容表意文字 |
| `U+3040–U+30FF` | 平假名和片假名 |
| `U+FF00–U+FFEF` | 全角和半角形式 |

示例：

| 文本 | 分类 |
| --- | --- |
| `中文` | 中文 |
| `粉底液` | 中文 |
| `かな` | 中文 |
| `カナ` | 中文 |
| `（中文）` | 中文；符号按钮仍可改变符号字体归属 |

## 3. 英文侧字符

除明确归入中文侧的字符外，其余字符默认使用英文字体，包括：

- 英文字母；
- 阿拉伯数字；
- 英文单词；
- 产品名称、产品型号、SKU 和版本号；
- 普通上标、下标字母和数字；
- 大于 25 的 ASCII 罗马数字；
- 容易与英文单词或编码混淆的字符序列；
- 较大、罕见或难以可靠识别的 Unicode 罗马数字字符；
- 用户点击“符号用英文”后，被识别为标点或符号的字符。

示例：

| 文本 | 分类 | 原因 |
| --- | --- | --- |
| `ABC` | 英文 | 普通英文字母 |
| `10MLX2` | 英文 | 字母数字编码 |
| `SKU-IV-A` | 英文 | 连字符连接的产品编码 |
| `MIX123` | 英文 | 英文/数字组合 |
| `MIX` | 英文 | 容易与英文单词混淆，采用保守规则 |
| `XXVI` | 英文 | 数值为 26，超过产品规定的识别上限 |

## 4. Unicode 罗马数字

Unicode 中存在专用罗马数字字符。当前只把常见的 1 至 12 归入中文字体：

- 大写：`Ⅰ Ⅱ Ⅲ Ⅳ Ⅴ Ⅵ Ⅶ Ⅷ Ⅸ Ⅹ Ⅺ Ⅻ`
- 小写：`ⅰ ⅱ ⅲ ⅳ ⅴ ⅵ ⅶ ⅷ ⅸ ⅹ ⅺ ⅻ`

对应范围：

- `U+2160–U+216B`
- `U+2170–U+217B`

更大的专用罗马数字，以及古体、罕见形式，统一使用英文字体。例如 `Ⅼ`、`Ⅽ`、`Ⅾ`、`Ⅿ`、`ↀ` 等。

## 5. ASCII 罗马数字

ASCII 罗马数字由普通大写英文字母 `I V X L C D M` 组成，因此不能只看到这些字母就判定为罗马数字。

只有同时满足以下条件时，才使用中文字体：

1. 整个连续 token 只包含 `I V X L C D M`；
2. token 符合标准罗马数字排列规则；
3. token 至少包含 `I`、`V` 或 `X`；
4. 换算后的数值不超过 25；
5. token 没有嵌入英文字母或阿拉伯数字中；
6. token 没有通过连字符 `-` 或下划线 `_` 与编码连接；
7. 单字符罗马数字必须具有足够明确的上下文，不能把普通英文单字母直接误判为罗马数字。

### 5.1 识别为罗马数字

| 文本 | 结果 |
| --- | --- |
| `I` 至 `XXV` | 在边界明确时使用中文字体 |
| `A IV B` | `IV` 使用中文字体，其余使用英文字体 |
| `第 XIV 章` | `XIV` 使用中文字体 |
| `Ⅰ`、`Ⅳ`、`Ⅻ` | 使用中文字体 |

### 5.2 不识别为罗马数字

| 文本 | 结果 | 原因 |
| --- | --- | --- |
| `XXVI` | 英文 | 数值超过 25 |
| `MIX` | 英文 | 数值大且与英文单词混淆 |
| `10MLX2` | 英文 | 嵌入数字编码 |
| `SKU-IV-A` | 英文 | 嵌入连字符编码 |
| `MIX123` | 英文 | 与数字直接连接 |
| `IV_CODE` | 英文 | 与下划线编码连接 |

## 6. 符号处理

标点和符号由 Unicode 的标点类 `P` 和符号类 `S` 识别。

面板提供两种显式选择：

- “符号用中文”：标点和符号使用中文字体；
- “符号用英文”：标点和符号使用英文字体。

罗马数字判断优先于符号按钮。因此，已明确识别的罗马数字不会因为切换符号按钮而改变归属。

成对标点的字符间距调整与字体归属相互独立：

- 中文全角成对标点可以进行外侧字距微调；
- ASCII 成对符号不套用中文全角标点的微调值；
- 符号使用中文字体或英文字体，不改变它是否属于中文全角标点。

## 7. 空格、换行和多行文本

- 空格、制表符和换行符会参与连续区间划分，但不会阻止后续行继续识别；
- 多行文本按整个 `TextNode.characters` 处理，而不是只处理第一行；
- Figma 范围索引采用 UTF-16 偏移；实现按 Unicode 码点遍历，同时保留正确的 UTF-16 起止位置；
- 某个区间写入失败时，插件会继续处理同一文本对象的其他区间和后续行；
- 最终会将失败区间汇总为“部分区间应用失败”，而不是提前中断整个文本对象。

## 8. 识别与应用的关系

同一套字符分类同时用于：

- 将文本拆分为中文字体区间和英文字体区间；
- 分别应用中英文字号；
- 点击“应用字体混排与颜色”时，分别应用中英颜色；
- 从已选文本中识别中文侧和英文侧的字体、字号与颜色。

颜色只在点击“应用字体混排与颜色”时修改。点击“应用字体混排”不会改变现有颜色。

## 9. 字体、颜色、字号的识别规则

“识别选中图层”与“应用字体混排”使用同一套中文/英文字符分类，避免面板识别结果与实际应用区间不一致。

### 9.1 字体识别

- 遍历所有选中的文本节点，而不是只读取第一个节点；
- 对每个非空白字符先按本文字符分类规则判断中文侧或英文侧；
- 中文侧取该侧遇到的第一个有效字符的 `fontName`；
- 英文侧取该侧遇到的第一个有效字符的 `fontName`；
- 如果一个侧完全不存在，则用另一侧的字体作为面板回填值，避免表单为空；
- Figma 返回 `figma.mixed`、缺失字体或读取异常时，该侧字体保持为空，不用另一侧的字体掩盖真实的不确定状态；
- 不会因为文本第一行是中文，就把整个多行文本识别成中文字体；每个字符区间独立判断。

### 9.2 颜色识别

- 中文侧颜色：读取中文侧第一个有效字符的 `getRangeFills()`；
- 英文侧颜色：读取英文侧第一个有效字符的 `getRangeFills()`；
- 只取第一个 `SOLID` 填充作为面板颜色；
- 渐变、图片填充或没有纯色填充时，该侧颜色保持为空或沿用另一侧的回填规则；
- 中文和英文颜色分别识别，不会因为第一字符颜色相同而把两侧强制设置成同色；
- 多个文本节点中同一侧存在不同颜色时，当前识别结果以首次有效颜色为面板代表值；应用时仍按当前配置写入所有区间。

### 9.3 字号识别

- 中文侧字号：遍历所有中文侧有效字符并收集字号；
- 英文侧字号：遍历所有英文侧有效字符并收集字号；
- 该侧只有一个字号时，回填该字号；
- 该侧存在多个字号时，字号输入框留空，并标记为“混合字号”；
- 中文侧字号混合不会影响英文侧字号，反之亦然；
- 多个文本节点中同一侧字号不一致时，也标记为混合字号；
- 小数字号会保留，不强制转成整数；
- 纯中文或纯英文文本缺少另一侧字符时，另一侧可以显示同类回填值，但这只是便于编辑，不代表文本实际包含另一侧字符。

### 9.4 识别结果的优先级

识别时按以下优先级处理：

1. 有效字符的实际字体、颜色和字号；
2. 同侧多个节点的共同值；
3. 同侧缺失时的另一侧回填值；
4. `mixed`、渐变、读取异常或多值冲突时保留为空，不能伪造确定值。

## 10. 字体、颜色、字号的应用规则

### 10.1 应用前置条件

- 应用前同时预加载中文字体和英文字体；
- 两种目标字体会去重加载，同一字体只加载一次；
- 任一目标字体明确不可用时，整个应用在修改文档前终止，并列出缺失字体；
- 字体加载超时不会被当成“字体不存在”，而是返回超时状态并提示重试；
- 未选中文本节点时不执行写入，并明确提示用户。

### 10.2 字体应用

- 先将文本节点整体设置为中文目标字体，确保 Figma 允许后续区间写入；
- 再按字符分类，将连续中文侧区间写入中文字体；
- 将连续英文侧区间写入英文字体；
- 每个区间使用 UTF-16 起止位置调用 Figma 的 `setRangeFontName()`；
- Unicode 补充字符按码点遍历，但区间位置仍使用 Figma 要求的 UTF-16 偏移；
- 字体写入失败只记录当前区间，继续处理同一文本对象的其他区间和后续行；
- 只有所有区间都成功时，该文本节点才计入成功数；若部分失败，会显示“部分区间应用失败”。

### 10.3 字号应用

- 中文侧只有在中文字号输入有效时，才对中文区间调用 `setRangeFontSize()`；
- 英文侧只有在英文字号输入有效时，才对英文区间调用 `setRangeFontSize()`；
- 输入为空表示“保留原字号”，不会写入默认值；
- 中文字号不会写到英文区间，英文大小也不会写到中文区间；
- 多行文本的每一行都按照字符区间应用字号；
- 某区间字号写入异常时，继续尝试其余区间，并在结果中记录失败范围。

### 10.4 颜色应用

- 只有点击“应用字体混排与颜色”时，才会设置颜色；
- 点击“应用字体混排”只改字体和字号，不改变颜色；
- 中文侧颜色只写入中文区间；
- 英文侧颜色只写入英文区间；
- 每个区间使用独立的纯色 `SOLID` Paint 调用 `setRangeFills()`；
- 颜色为空时不写入该侧颜色，保留原颜色；
- 颜色写入异常不会阻止后续行和其他语言区间继续应用；
- 多行文本不会只对第一行设置颜色；每一行都按完整 UTF-16 区间处理。

### 10.5 应用结果计数

| 状态 | 含义 |
| --- | --- |
| 成功 | 文本对象的字体、字号、颜色和字距处理均完成 |
| 部分区间应用失败 | 至少一个区间写入失败，但其它区间继续执行 |
| 字体不可用 | 目标字体加载失败，文档未开始修改 |
| 字体加载超时 | 未确认字体加载完成，文档不开始修改 |
| 无文本节点 | 当前选择中没有可处理的文本图层 |

错误提示中的节点名和区间位置用于定位问题，不代表整个文档的所有文本都失败。

## 11. 保守策略与已知歧义

ASCII 罗马数字和英文使用相同的拉丁字母，无法仅凭字符做到百分之百的语义判断。例如 `MIX` 在形式上可以被解释成罗马数字，但更常见的含义是英文单词 `mix`。

本项目采用以下产品策略：

- 宁可把难以判断的内容留在英文字体，也不把正常英文误套为中文字体；
- 只自动识别 25 以内、格式合法且边界明确的 ASCII 罗马数字；
- 超过 25、嵌入编码或存在明显英文歧义时，统一使用英文字体；
- 如果后续出现新的业务文本模式，应增加通用边界规则和回归测试，不针对单个截图字符串硬编码。

## 12. 回归测试要求

修改识别规则时，至少验证以下场景：

- 纯中文、纯英文和中英混排；
- 单行和多行文本；
- Unicode 罗马数字；
- ASCII 罗马数字 `I` 至 `XXV`；
- `XXV` 与 `XXVI` 的边界；
- `MIX` 等英文歧义词；
- 型号、SKU、版本号、连字符和下划线编码；
- 普通上标和下标字符；
- 符号使用中文/英文两种状态；
- 某一区间失败后，其余区间和后续行仍能继续应用；
- 字体、字号和颜色分别应用到正确区间。

## 13. 字体列表与字体选择规则

字体下拉列表不是直接把 Figma 返回的扁平字体组合全部展示，而是先按字体家族聚合：

- Figma 返回的每项由 `family + style` 组成；
- 相同 `family` 的不同 `style` 合并到同一个字体家族；
- 同一家族内重复的 style 去重；
- 字体家族按名称排序，保证每次打开顺序稳定；
- 用户先选择字体家族，再选择具体字重/样式；
- 中文字体和英文字体分别保存，不能因为同一家族或同一字号而合并；
- 目标字体配置最终必须同时包含 `family` 和 `style`。

字体下拉列表加载属于 UI 初始化流程。字体列表加载较慢时不应阻塞“识别选中图层”，识别可以先完成，字体列表随后异步加载。

## 14. 字体加载、缓存与超时规则

- 中文字体和英文字体并行预加载；
- 相同 `family + style` 在同一次应用中只加载一次；
- 成功或正在加载的字体请求可以复用；
- 加载失败的请求从缓存移除，允许下次重试；
- 单次字体加载超时时间为 4000ms；
- 超时和“字体不存在”必须区分：
  - `missing`：明确不可用，返回缺失字体列表；
  - `timeout`：尚未确认结果，返回超时状态；
- 目标字体未确认加载完成时，不开始修改文本，避免生成半成品；
- 选中图层原本使用的旧字体不需要全部预加载，应用流程会先整体设置目标中文字体，再写入各区间；
- 预加载字体方案只读取方案中的中文字体和英文字体，并按字体去重。

## 15. 应用流程的完整顺序

一次“应用字体混排”的完整顺序如下：

1. UI 检查中文字体和英文字体是否都已选择；
2. UI 读取中文/英文字号、颜色、符号侧和成对标点外侧字距；
3. UI 根据按钮决定 `applyColors` 是否为 `true`；
4. 主进程取得所有选中的文本节点；
5. 主进程立即回传 `font-mixer-start`，UI 显示处理中状态；
6. 并行加载两个目标字体；
7. 目标字体缺失或超时时，在文档写入前返回结果；
8. 对每个文本节点先整体设置中文目标字体；
9. 遍历完整文本，按中文侧/英文侧切分连续区间；
10. 每个区间依次应用字体、字号和可选颜色；
11. 处理中文全角成对标点外侧字距；
12. 汇总成功节点和失败区间；
13. 回传 `font-mixer-done`；
14. UI 和 Figma 通知分别显示应用结果。

如果一个文本对象有多行，步骤 9 至 12 会覆盖整个 `characters` 字符串，不以视觉上的第一行、换行符或文本框高度作为终止条件。

## 16. 字体混排方案规则

字体混排方案保存以下字段：

- 方案名；
- 中文字体 `family + style`；
- 英文字体 `family + style`；
- 中文字号；
- 英文字号；
- 中文颜色；
- 英文颜色；
- 符号字体侧。

方案行为：

- 选择方案只修改面板表单，不直接修改画布；
- 选择方案后，自动识别结果不能覆盖方案中的表单值；
- 再次点击当前方案可以取消方案选择，恢复识别回填；
- 没有选择方案时，选区识别结果可以回填表单；
- 已选择方案时，识别请求迟到也不能覆盖用户刚选择的方案；
- 方案支持新建、更新、重命名、删除、上移和下移；
- 内存状态是当前运行时的主要数据源；
- `localStorage` 只作为可用环境中的快速缓存；
- Figma 插件实际持久化使用 `figma.clientStorage`；
- 插件重新打开后从主进程回传的 clientStorage 数据恢复方案。

## 17. UI 状态和错误反馈规则

字体混排 UI 必须区分以下状态：

- 未选择文本：提示先选择文本图层；
- 正在加载字体：显示处理中的文本节点数量；
- 字体不可用：列出不可用的目标字体；
- 字体加载超时：提示重试，不将超时说成字体不存在；
- 全部成功：显示已应用的文本节点数量；
- 部分节点或区间失败：显示成功节点数、失败节点数、节点名和失败原因；
- 主进程发生致命异常：显示“应用失败”和异常信息；
- 20 秒未收到主进程结果：UI 显示主进程可能无响应的提示，不无限停留在处理中。

通知与面板结果必须使用同一份主进程结果，不能一个显示成功、另一个显示失败。

## 18. 字距和成对标点规则

字体混排应用结束后还会处理中文输入法成对标点的外侧字距：

- 支持圆括号、方括号、花括号及多种中日韩成对标点；
- 使用栈匹配嵌套成对符号；
- 只有成对符号两端都是中文/全角 CJK 字符时，才使用配置的 `pairedOuterValue`，默认值为 `-45`；
- ASCII 成对符号如 `()`、`[]`、`{}` 不使用中文全角缩进规则，明确写入 `0`；
- 字符字体归属按钮不改变成对标点字距判断；
- 成对标点字距处理失败会作为该文本对象的部分区间失败记录，但不会阻止其他文本节点继续应用。

## 19. 失败隔离和一致性规则

- 字体目标加载失败：在写入前整体终止，避免所有节点形成半成品；
- 单个文本节点整体属性设置失败：只标记该节点失败，后续节点继续；
- 单个区间字体写入失败：继续处理该节点的后续区间；
- 单个区间字号写入失败：继续处理其它区间；
- 单个区间颜色写入失败：继续处理其它区间和后续行；
- 字距写入失败：记录该节点失败，但不影响其它节点；
- 一个节点只要有区间失败，就不能计入完整成功数；
- 失败原因最多保留有限长度，避免面板被异常文本撑满；
- 失败结果必须携带文本节点名，便于在 Figma 中定位；
- 不使用字体回读结果作为唯一成功判据，因为 Figma 对跨样式范围的回读可能返回首段字体或 `mixed`，造成“实际已应用但面板报错”。

## 20. 代码与文档同步要求

以后修改字体混排功能时，必须同时检查：

1. 字符分类函数；
2. ASCII 和 Unicode 罗马数字边界；
3. UTF-16 区间切分；
4. 字体加载与超时；
5. 字体、字号、颜色三个属性的区间写入；
6. 多行文本；
7. 成对标点字距；
8. 方案保存和识别回填守卫；
9. UI 成功/失败/超时反馈；
10. `src` 源码、`dist` 构建产物和回归测试。

文档中的示例是规则示例，不应被实现为针对单个字符串的硬编码特例。新增规则必须优先抽象为边界、token、脚本类别或上下文规则，并增加正例和反例测试。
