# Photoshop 字距微调调研：度量标准与视觉

字符面板中「设置两个字符间的字距微调」（Kerning）用于调整**两个字符之间**的间距，度量单位为 1/1000 em，随字号等比缩放。下拉菜单除数值外提供两种自动模式：**度量标准**（Metrics）与**视觉**（Optical）。

## 功能边界

| 易混控件 | 触发条件 | 作用范围 |
| --- | --- | --- |
| 字距微调（本功能） | 插入点放在两个字符之间 | 单个字符对 |
| 字距调整（Tracking） | 选中一段文字范围 | 选区或整个文本块 |

两者结果**累加**：可先逐对微调，再整体收紧或放宽，字符对的相对关系不变。选中文字范围后无法手动微调，只能用字距调整——这是「调了没反应」的常见原因。

## 两种自动模式对比

| | 度量标准（Metrics） | 视觉（Optical） |
| --- | --- | --- |
| 数据来源 | 字体文件内置的 kern 表（字距微调对） | Adobe 专利算法，按相邻字形轮廓即时计算 |
| 是否依赖字体质量 | 强依赖；字体缺失 kern 表时几乎无效 | 不依赖；劣质字体也能得到合理间距 |
| 结果稳定性 | 稳定，跨版本不重排 | Adobe 会调整算法，新版本可能引起重排 |
| 适用场景 | 正文、长段落、专业付费字体 | 大标题、混排字体或字号、免费/劣质字体 |
| 主要风险 | 字体质量差时间距失控 | 破坏设计师的字距节奏；小字号正文易显跳动 |
| 行业倾向 | 默认首选 | 救急选项，用后需目检 |

## 度量标准（Metrics）

读取字体设计师写进字体文件的 kern 对。典型修复对象如 `LA、P.、To、Tr、Wa、Yo` 等视觉上易失衡的组合。使用该模式即呈现字体设计本来的样子，Adobe 官方将其设为默认。

局限：一行内混用**不同字体或不同字号**时 kern 表失效；免费或粗制字体往往只有少量 kern 对甚至没有。

## 视觉（Optical）

忽略字体数据，根据相邻字符的形状重算间距。业界描述其思路接近 *bubble kerning*：同时考虑字形间的最小距离与两字之间的空白总面积，并取字体基础间距的少量样本推导其余配对。是否等同 Zapf 的 HZ 程序（Adobe 购自 URW 的专利）在字体设计圈仍有争议。

已知问题：

- 会推翻字体设计师的字距设计。TypeDrawers 上以 Miller Text 排「lithium」的例子显示，算法推开直笔画、收紧 `it`/`iu`，破坏字干节奏（stem rhythm）。
- 只优化局部空白，不考虑字干节奏，对衬线体的破坏大于无衬线体。
- 算法随版本变化，同一文件可能在新版本中重排。

## 使用建议

- 正文、长段落、专业字体 → **度量标准**。
- 大标题、Logo 字、一行内混排、字体缺 kern 表 → **视觉**，之后目检。
- 中文、日文场景两个选项基本无关：CJK 字形近等宽方块且字体普遍无 kern 表，应使用字距调整（Tracking）或 CJK 版式功能。
- 手动微调：插入点置于两字之间，`Alt/Option + ←/→` 增减，或在框内输入数值；设为 0 表示关闭微调。

## 常见坑

1. 默认值可在**未打开任何文档**时于字符面板修改，之后新文档沿用该默认。
2. 视觉模式即时计算，改字号、改字体或重新编辑文字层都可能引起换行变化，交付前需复查。
3. 面板显示「度量标准/视觉」表示该字符对为自动处理；显示数字表示被手动改过，可用于排查交接文件。

## 对本插件的参考价值

Figma 文本仅有字距调整（letter spacing），不提供度量标准/视觉的微调模式切换，OpenType kerning 默认生效。字体混排功能若未来支持字符间距，单位与 Photoshop 一致（em 的千分比），但无字符对级别的微调 API，自动微调只能在应用前于文本层面预处理。

## 插件当前实现

本仓库已提供一个近似的自动字符对微调功能，入口位于英文设置卡片右上角的「自动微调」按钮。规则如下：

- 成对符号（如 `()`、`[]`、`（）`、`【】`、`“”`、`「」`）的外侧间距写入 Figma `-45%`。
- 单独出现的 Unicode 标点/符号只调整符号右侧，写入 `-30%`。
- `#`、`*`、`¥`、`·`、`~`、`%`、`&` 这 7 个单独符号排除在自动调整之外。
- 支持混合字体文本，会先加载各字体区段；字体不可用时跳过失败节点并报告数量。
- 每次点击都会重新写入绝对字距值，不会累计叠加。

该功能依赖 Figma 的 `setRangeLetterSpacing`，属于规则化近似，不读取字体轮廓，也不等同 Photoshop Optical Kerning。
